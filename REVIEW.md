# Безопасность и найденные ошибки

Разбор безопасности и кода расширения. Каждое замечание: суть, серьёзность, статус. Исправления закрыты тестами из `tools/` (`smoke_test.js` — сценарии 1–24, `notification_test.js`, `sound_test.js`).

## 1. Безопасность

| # | Находка | Серьёзность | Статус |
|---|---|---|---|
| S1 | Ключ доступа к API mail.ru хранился в `chrome.storage.local`, то есть на диске | High | **Исправлено**: ключи только в `chrome.storage.session` (в памяти, стираются при закрытии браузера); запасного пути на диск нет (сценарий 11, notification_test) |
| S2 | `getState`/`state-updated` рассылали состояние вместе с ключом всем страницам расширения | Medium | **Исправлено**: ключ не входит в состояние |
| S3 | `chrome.runtime.onMessage` принимал сообщения от любого отправителя | Medium | **Исправлено**: `isTrustedSender()` принимает только страницы `chrome-extension://<id>/` (сценарий 10) |
| S4 | Адрес аватара из ответа сервера попадал в `<img>` без проверки протокола | Low | **Исправлено**: `safeAvatarUrl()` пропускает только `https:` |
| S5 | Поля письма хранились без ограничения длины | Low | **Исправлено**: превью до 500 символов, тема до 300, имя до 200, адрес до 254 (сценарий 24) |
| S6 | Связь «уведомление ↔ письмо» лежала на диске | Low | **Исправлено**: в `chrome.storage.session` |
| S7 | Ключ передаётся в строке GET-запроса | Info | **Остаточный риск**: так устроен API mail.ru; защищено TLS |
| S8 | Список последних непрочитанных писем (отправитель, тема, превью) хранится в `chrome.storage.local` | Info | **Осознанно**: нужен, чтобы не уведомлять о старых письмах после перезапуска; описан в README, стирается кнопкой «Сбросить состояние» |
| S9 | Права расширения | Info | `alarms`, `notifications`, `storage`, `offscreen` (звук) и доступ к четырём адресам mail.ru. Пароль и cookies расширение не читает: запросы идут с сессией браузера. CSP Manifest V3 по умолчанию, без inline-скриптов и `eval`. Сторонним сервисам данные не отправляются |

## 2. Код

| # | Находка | Статус |
|---|---|---|
| C1 | `background.js` смешивал хранилище, запросы, уведомления и логику | **Исправлено**: модули `lib/store.js`, `lib/mailapi.js`, `lib/notify.js`, `lib/util.js`; `background.js` управляет проверками и командами |
| C2 | Дублирование в «Прочитано»/«Удалить» | **Исправлено**: общий `messageActionCore()` и `removeFromState()` |
| C3 | Настройки не проверялись | **Исправлено**: `saveSettings()` принимает только известные ключи и настоящие булевы значения, `notificationMode` — только `native`/`window`, интервал 1–60 мин, число писем 10–200, мелодия — из списка. Страница настроек не сохраняет форму, пока настройки не загружены (notification_test) |
| C4 | Магические строки и регулярные выражения | **Исправлено**: именованные константы в `lib/mailapi.js` |

## 3. Аудит по Manifest V3 (версии 1.4.2–1.4.3)

| # | Находка | Статус |
|---|---|---|
| A1 | `&gt;` в теме письма не раскодировался, `&amp;lt;` раскодировался дважды | **Исправлено**: один проход по таблице сущностей (сценарии 14, 19) |
| A2 | Фоновая проверка и «Прочитано»/«Удалить»/«Открыть» одновременно перезаписывали состояние: прочитанное письмо возвращалось, возможны повторные уведомления | **Исправлено**: все изменения состояния идут по очереди (`withStateLock`), запросы к mail.ru — вне очереди (сценарий 15) |
| A3 | Каждое пробуждение фонового модуля откладывало проверку на полный интервал | **Исправлено**: таймер пересоздаётся только при смене интервала (сценарий 16) |
| A4 | Одновременные сигналы создавали offscreen-документ дважды, звук мог потеряться | **Исправлено**: одно создание на всех, проверка `runtime.getContexts`, отдельная ветка для Chrome 110–115 (notification_test) |
| A5 | Звук играл отдельно для каждого ящика | **Исправлено**: один сигнал на проверку (сценарий 17) |
| A6 | Доступ ко всем поддоменам `https://*.mail.ru/*`, хотя запросы идут на 4 адреса | **Исправлено в 1.4.3**: оставлены только `portal.mail.ru`, `auth.mail.ru`, `e.mail.ru`, `mailru-checker-api.e.mail.ru`. Вход, счётчик, список и «Прочитано» проверены вручную на живой сессии; сценарий 21 следит, чтобы каждый адрес запроса был покрыт разрешением |
| A7 | Ключ доступа мог попасть на диск, если нет `chrome.storage.session` | **Исправлено**: запись падает с ошибкой (notification_test) |
| A8 | После «Открыть письмо», «Прочитано» или «Удалить» проверка могла вернуть письмо, если mail.ru ещё не снял флаг «не прочитано», и прислать повторное уведомление | **Исправлено**: такие письма не уведомляют повторно не меньше 10 минут и не меньше двух интервалов проверки (сценарии 18, 20) |
| A9 | Сводное уведомление: «3 новых писем» | **Исправлено**: склонение — «1 новое письмо», «3 новых письма» (сценарий 19) |
| A10 | Строка письма в попапе возвращалась на секунду, если во время «Прочитано» заканчивалась фоновая проверка | **Исправлено**: строка скрыта до ответа, при ошибке возвращается. Проверено на стенде в браузере с подменой API; автотеста нет |

| A11 | «Сбросить состояние» не очищал очередь окна уведомлений с темами и началом писем | **Исправлено** (сценарий 23); id открытого окна сохраняется, чтобы не открылось второе |
| A12 | Свой звук пользователя | Принимаются MP3/WAV/OGG до 1 МБ, только если браузер смог их разобрать. Файл хранится в `chrome.storage.local`. Offscreen-документ играет только `sound/*.wav` из пакета или `data:audio/…` и только по сообщению самого расширения; если свой файл не воспроизвёлся, звучит стандартный сигнал (sound_test) |

## 4. Ресурсы

- Значки созданы скриптом `tools/make_icons.py`, шесть встроенных сигналов — `tools/make_sound.py` (синтез, без сторонних сэмплов).

## 5. Сознательно не сделано

- Чтение страницы mail.ru скриптом на странице: JSON-API стабильнее и безопаснее.
- Перенос работы с очередью окна уведомлений из маршрутизатора `background.js` в `lib/notify.js`: меняет договорённость с `notice.js`, пользы для пользователя нет.
- UI-тесты страницы настроек: сценарии звука проверены вручную на стенде с подменой API Chrome.
